# Truth table instead of a geometric 2D plane

The most common way to teach a perceptron learning AND/OR/XOR is geometrically — plot the 4 input combinations on a 2D plane and draw the decision boundary line through them. We built a working prototype of exactly that (SVG plane, draggable test point, boundary line) and rejected it in favor of a truth table: all 4 fixed input rows shown at once, each with its expected output, live weighted sum, and actual output as inline columns. This was a deliberate choice for directness — the audience is meant to read "does the AND row say 1 now?" off a table rather than infer a classification from which side of a line a dot falls on — at the cost of the geometric intuition for *why* XOR specifically fails (no line can separate the corners), which now has to be explained verbally rather than seen.
